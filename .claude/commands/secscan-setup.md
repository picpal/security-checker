# secscan 환경 세팅

secscan 이 필요로 하는 스캐너·런타임이 이 PC 에 갖춰져 있는지 확인하고, 빠진 것을
사용자 승인을 받아 하나씩 채운다.

## 0단계 — 파이썬 환경

`.venv/bin/secscan` 이 있는지 확인한다. 없으면 다음을 **제안하고 승인받은 뒤** 실행:

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
```

이후 모든 명령은 `.venv/bin/secscan` 을 쓴다. (venv 없이 `python3 -m secscan` 도 동작한다.)

## 1단계 — 진단

```bash
.venv/bin/secscan doctor
```

출력 형식:

- `✓` 충족 · `✗` 미설치 · `⚠` 설치는 됐으나 버전/상태 문제
- 미충족 항목 아래 `→ <설치 명령>` 이 붙는다
- `(미설치, 선택)` 로 표시된 항목은 **없어도 기본 점검이 돌아간다**

## 2단계 — 설치 순서 정하기

미충족 항목을 이렇게 나눈다:

| 우선순위 | 대상 | 이유 |
|---|---|---|
| 1 | `(선택)` 표시가 **없는** 미충족 항목 | 없으면 점검이 막힌다 |
| 2 | `(선택)` 표시가 있는 항목 | 특정 프로파일/기능에서만 필요 |

`⚠`(버전 문제)는 `✗`(미설치)와 같은 우선순위로 다룬다 — doctor 가 이미 미충족으로 판정한 것이다.

## 3단계 — 하나씩 확인받고 설치

각 항목마다 AskUserQuestion 으로 묻는다. 한 번에 하나씩. 물을 때 반드시 포함할 것:

- 어떤 도구이고 **무엇에 쓰이는지** (doctor 가 출력한 purpose)
- **doctor 가 출력한 설치 명령을 그대로** — 명령을 창작하지 말 것
- 차단 항목인지 선택 항목인지

선택지는 `설치한다` / `건너뛴다` / `명령만 보여주고 내가 직접 친다` 세 가지로 준다.
`brew install` 같은 명령은 수 분이 걸릴 수 있으니, 오래 걸릴 수 있다고 미리 알린다.

설치가 실패하면 **다음 항목으로 넘어가고**, 실패 사실을 기록해 뒀다가 마지막에 함께 보고한다.
하나 실패했다고 전체를 멈추지 않는다.

## 4단계 — 재검증

설치를 한 건이라도 했으면 `doctor` 를 다시 실행한다. 남은 미충족 항목이 있으면 2단계로 돌아간다.
사용자가 건너뛴 항목은 다시 묻지 않는다.

## 마무리 보고

| 항목 | 내용 |
|---|---|
| 지금 쓸 수 있는 프로파일 | 아래 표 기준 |
| 설치한 것 / 건너뛴 것 / 실패한 것 | 각각 나열 |

프로파일별 필요 도구:

| 프로파일 | 필요 |
|---|---|
| `quick` | trivy, gitleaks |
| `accurate-sca` | trivy, osv-scanner, depscan, atom |
| `standard` | 위 + semgrep |
| `deep` | 위 + spotbugs, FindSecBugs 플러그인 jar, JDK, 빌드도구 |

마지막에 `/security-check <경로 또는 git URL>` 로 점검을 시작할 수 있다고 안내한다.

**doctor 가 모두 `✓` 라고 해서 "완벽하다"고 단정하지 말 것.** doctor 는 설치 여부와
버전만 본다. 실제 스캔은 대상 프로젝트의 빌드 상태에 따라 부분 실패할 수 있다.
